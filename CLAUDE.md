# Журнал съёмок — правила для Claude

Личный local-first журнал фотоохоты Алексея: читает каталог Lightroom Classic, собирает дни и места съёмок, показывает погоду, солнце, карту, планирует выходные, подтягивает наблюдения iNaturalist и полевые данные (GPX, заметки с телефона).
Общаемся по-русски, на «ты».

## Запуск и проверка

- Окружение: WSL Ubuntu, Python 3.12, `.venv` в корне (`source .venv/bin/activate`).
- Сервер: `./run.sh` → http://localhost:8765 (uvicorn с `--reload`, правки подхватываются сами).
- Демо-база с выдуманными данными: `python scripts/make_demo.py`, запуск `JOURNAL_DB=data/demo.db ./run.sh`. В демо синхронизация с каталогом отключена.
- Проверяй изменения на демо-базе или на копии базы, а не на `data/journal.db`. Перед миграцией схемы сделай копию `data/journal.db`.
- Внешние API (Open-Meteo, iNaturalist, Nominatim) — не чаще, чем указано в модулях; iNat ~1 запрос/с.

## Устройство

- `app/main.py` — FastAPI, все эндпоинты `/api/...`.
- `app/db.py` — схема SQLite и миграции (`_migrate`, `field.ensure_schema`). Миграции только добавляют, данные не теряются.
- `app/lrcat.py` — чтение каталога Lightroom: временная копия `.lrcat` вместе с `.lrcat-wal`, разбор папок «дата_Место», дедупликация дисков D/E/F.
- `app/sync.py` — синхронизация каталога → база журнала. Заметки и вручную назначенные места не перезаписываются.
- `app/locations.py` — места, синонимы, правила из `locations.txt`.
- `app/weather.py`, `app/sun.py`, `app/plan.py`, `app/inat.py` — погода, солнце, «Выходные», iNaturalist.
- `app/field.py` — GPX из папки дня, координаты кадров по треку, находки, безопасная выгрузка.
- `app/previews.py`, `app/species.py` — превью из `Previews.lrdata`, распознавание видов (`python -m app.species …`), региональный список iNat. Зависимости — `requirements-species.txt`, веса и эмбеддинги — в `data/`.
- `static/index.html` — весь фронтенд в одном файле, vanilla JS. Leaflet лежит в `static/vendor/leaflet`.
- Новые зависимости (pip/npm/CDN) — только после согласования с Алексеем.

## Что нельзя трогать

- Каталог Lightroom, NEF и XMP только читаем. Никогда не пишем в каталог и в файлы снимков. Координаты и метки живут в базе журнала; в Lightroom их потом будет записывать плагин через его API.
- В git не должны попадать: `config.json`, `locations.txt`, `data/`, `scan*.txt`, `*.zip`, любые GPX и фото Алексея, реальные координаты его мест. Перед коммитом проверь `git status`.
- Скриншоты и примеры для README — только из демо-базы с выдуманными местами.
- Находки (норы, дупла, гнёзда) по умолчанию скрытые: наружу (GPX, iNat, Lightroom) — только огрублённые координаты (~1 км), трек вокруг вырезается. Не ослабляй это без явной просьбы.
- Единственный публичный контакт — Telegram @Perevezentsev. Почту Алексея нигде не указывать.

## Предметные договорённости

- Время съёмки в каталоге — местное без пояса; пояс +3 (Петербург). GPX — в UTC.
- Отбор в Lightroom: ★2 и выше — отобран, ★5 — обработан. Флаги Pick не используются.
- Папка дня съёмки (подпапки необязательные):
  ```
  ДДММГГГГ_Место\
    <подпапки импорта Lightroom>\   NEF
    Трек\          GPX (ищем и в корне дня)
    С телефона\    фото-заметки с телефона (старое имя «Телефон» тоже понимаем)
    Видео\         видео, не в Lightroom — пока не читаем
    Аудио\         звук — пока не читаем
  ```
  Имена подпапок — константы `TRACK_DIRS`, `PHONE_DIRS`, `VIDEO_DIRS`, `AUDIO_DIRS` в `app/field.py`.
  Сюда, как и в каталог, ничего не пишем.
- Место дня берётся из имени папки «дата_Название»; день может относиться к нескольким местам; у места бывают точки со сторонами берега (`facing`).

## Git и релизы

- Коммиты, теги и push делает Алексей сам, если не попросил иначе. Предлагай готовые команды.
- Почта для коммитов — только noreply: `15665091+Perevezentsev@users.noreply.github.com`.
- При каждом заметном изменении обновляй `CHANGELOG.md`: раздел `## [Не выпущено]` наверху.
  - Формат Keep a Changelog по-русски, SemVer, пока 0.x.
  - Пишем пользу для Алексея, а не список коммитов. Под версией — одна строка-итог.
  - Разделы: «Добавлено», «Изменено», «Исправлено», при необходимости «Приватность» и «Дальше».
- Релиз: раздел переименовывается в `## [X.Y.Z] — ГГГГ-ММ-ДД`, затем `git tag -a vX.Y.Z -m "vX.Y.Z — Название"` и push тега. GitHub Actions (`.github/workflows/release.yml`) создаёт релиз из этого раздела.

## Как работать с Алексеем

- Когда действие выполняет он сам (команды, проверки в браузере, Lightroom), — один шаг за сообщение, дальше ждать его ответа.
- Сначала коротко: что собираешься сделать. Большие изменения — с планом перед началом.
- После правок: что изменилось и как проверить, в 2–3 строки.
